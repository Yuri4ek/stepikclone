# КодСтарт — образовательная платформа ФСП Чувашии

Веб-платформа дистанционной подготовки школьников 1–9 классов по спортивному программированию (по устройству близка к Stepik).
Ученик проходит курс сам, куратор сопровождает и проверяет работы, администратор собирает и публикует курсы.

- Backend — FastAPI + PostgreSQL: [`backend/README.md`](backend/README.md)
- Frontend — React + TypeScript + Vite: [`frontend/README.md`](frontend/README.md)
- Полный гайд: роли и экраны, устройство фронтенда, бэкенда и базы, деплой с Docker — [`docs/GUIDE.md`](docs/GUIDE.md)
- Лицензия — [MIT](LICENSE)

## Запуск

### Docker (всё сразу)

```bash
docker compose up --build
```

- фронтенд — http://localhost:3000, API — http://localhost:8000 (Swagger — `/docs`)
- контейнер бэкенда сам выполняет `alembic upgrade head` и заливает демо-данные, если база пустая
- адрес API вшивается во фронтенд при сборке: `VITE_API_URL=https://api.example.org docker compose up --build`
- на сервер с доменом и HTTPS: `docker-compose.prod.yml` + `Caddyfile`, см. [гайд, раздел 9](docs/GUIDE.md#9-деплой-с-docker)

### Локально

```bash
docker compose up -d db                      # Postgres на порту 5433

cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
alembic upgrade head
PYTHONPATH=. python -m app.seed.run --force  # курсы из пакета содержания + демо-ученики
uvicorn app.main:app --reload --port 8000

cd ../frontend
npm install
echo 'VITE_API_URL=http://localhost:8000' > .env
npm run dev                                  # http://localhost:5173
```

## Что сделано

**Содержание.** Базовый пакет Федерации перенесён в модель целиком: 3 курса, 9 модулей, 30 шагов
(`backend/app/seed/package_courses.py`). У курса есть паспорт (классы, объём, инструмент, цель). Блочные программы
Scratch и MakeCode хранятся текстом, как в пакете, и рисуются блоками. Правильные ответы, критерии, эталонные решения
и скрытые тесты ученику не отдаются.

**Типы шагов — расширяемые.** Шаг = механизм проверки (`kind`) + вид у ученика (`content.type`).

| Тип из пакета | kind | content.type | Проверка |
|---|---|---|---|
| Теория | theory | theory | засчитывается при прочтении |
| Контрольный вопрос | quiz | quiz / answer | один или несколько вариантов, ответ числом — сразу |
| Scratch: разбор с ответом | quiz | scratch_answer | ответ числом — сразу |
| Scratch: проект по ссылке | task | scratch | куратор |
| Minecraft Education | task | minecraft | скриншот + ссылка на MakeCode, куратор |
| Проект | task | project | ссылка / скриншот / текст по настройке, куратор |
| Задача с тестами | code | algo | прогон на сервере по всем тестам — сразу |

Механизмы проверки — реестр `backend/app/steps/registry.py`; колонка `steps.kind` — строка, поэтому новый механизм
не требует миграции. Новый вид шага на существующей проверке («Робототехника» с ручной проверкой) — это только
новый модуль во фронтенде (`frontend/src/entities/step/ui/step-types`), бэкенд и база не меняются.
Шаг незнакомого фронтенду типа всё равно откроется общим плеером своей проверки.

**Проверка.** Автоматическая: варианты, ответ числом (без учёта пробелов, регистра, «3,5»/«3.5»), задачи на Python —
прогон на сервере с ограничениями времени и памяти, вердикты OK / WA / TLE / RE / ML. Ручная: работа уходит куратору,
он принимает с баллами или возвращает с комментарием. Работа на проверке и возвращённая работа не блокируют путь —
ученик идёт дальше.

**Прогресс и рейтинг.** Рейтинг курса = набранные баллы ÷ все баллы обязательных шагов × 100; ручная и автоматическая
проверка весят одинаково. Ученик видит расшифровку: сколько дала автопроверка, сколько куратор, сколько ждёт
проверки, сколько ещё можно получить; место в группе курса и серию дней подряд.

**Куратор.** Очередь проверки, карточка работы с критериями, вопросы учеников по конкретному шагу, ученики своих курсов
с уровнем отставания и причинами. Отставание ловится заранее: «заходит, но N дней без продвижения», «N неудачных
попыток на шаге», «не исправляет возвращённую работу», «отстаёт от медианы группы» — а не только «давно не заходил».

**Администратор.** Курсы и черновики, конструктор модулей, уроков и шагов с редактором под каждый тип и предпросмотром
«глазами ученика», паспорт и обложка курса, публикация и снятие с публикации (у записанных учеников курс остаётся),
назначение и снятие кураторов, запись и отчисление учеников, создание пользователей.

## Что не успели / ограничения

- Прогон решений изолирован лимитами CPU, памяти и размера вывода и запускается от отдельного пользователя `judge`
  без доступа к коду бэкенда (в Docker). Сеть у решения не отключена; для продакшена прогон стоит вынести в отдельный
  изолированный воркер (nsjail / gVisor) и очередь. Локально на macOS лимит памяти не работает — превышение видно как TLE.
- Куратор закрепляется за курсом целиком; разбиения учеников курса на группы по кураторам нет.
- Уведомлений (почта, Telegram) о возврате работы и ответе на вопрос нет — ученик видит их на главной и на шаге.
- Тексты задач курса «Алгоритмика» оставлены как в пакете (на «вы», олимпиадный стиль); интерфейс ученику пишет на «ты».
- Старые демо-курсы-заглушки не входят в seed по умолчанию: `python -m app.seed.run --force --legacy`.
